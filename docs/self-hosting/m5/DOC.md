# M5.4: documentation and command-line helpers (D277)

Scope: B7's S6 helpers for the documentation tools and the archive command
line: the split and line scans, entity conversion, the Java identifier-part
tag predicate, and the remaining discovery helpers (IronDoc's source walks;
its version resource is D269's BuildIdentity). They prepare S6's ports of
DocComment, DocModel, MarkdownDoclet, IronDoc, IronDocOptions and IronJarMain;
they are not those ports.

| Port source | Replaces |
| --- | --- |
| [DocText.iron](../../../compiler/src/main/ironwood/ironwood/compiler/port/DocText.iron) | DocComment's `\R` split, `\s+` head and tail, comment-star and code-tag regexes, entity matcher, backtick matcher, `stripLeading`, `regionMatches(true, ...)` and tag scan; MarkdownDoclet's `\s+` and `\s*\R\s*` replacements and identifier-run matcher; IronDoc's package-name `matches`; DocModel.Member.anchor's code points, `appendCodePoint` and hex |
| [JavaIdentifiers.iron](../../../compiler/src/main/ironwood/ironwood/compiler/port/JavaIdentifiers.iron) | `Character.isJavaIdentifierPart(char)` and `(int)`, generated by [JavaIdentifierTable.java](doc-evidence/JavaIdentifierTable.java) |
| [LinkRenderer.iron](../../../compiler/src/main/ironwood/ironwood/compiler/port/LinkRenderer.iron) | DocComment.render's `BiFunction<String, Boolean, String>` |
| [FileCollector.iron](../../../compiler/src/main/ironwood/ironwood/compiler/port/FileCollector.iron) (depth) | IronDoc's `Files.walk(root)` and `Files.walk(directory, 1)` selections |

The tag scan keeps DocComment's UTF-16 `char` loop: the part predicate is
applied from the first position after `@`, with no identifier-start or
keyword rule and no surrogate pairing, so a supplementary letter ends the name
at its high surrogate, as in Java.

## Semantics checked against the Java tools

[DocTextReference.java](doc-evidence/DocTextReference.java) runs the baseline's
own methods by reflection (DocComment's head, tail, entities, longestTicks and
parse; IronDoc.validatePackage; DocModel.Member.anchor) and the exact
expressions of the other call sites over a corpus of 83 hand-picked and 3,000
seeded random inputs drawn from line breaks, regex and Unicode spaces, `*`,
`<code>` and `</code>` pieces, entity fragments, backticks, dots, `$`,
case-folding letters (`İ`, `ı`, `ſ`, the Kelvin sign) and paired and isolated
surrogates; 438 tag suffixes (the nine block tags, near misses, combining
marks, soft hyphen, zero-width and format characters, currency, connecting
punctuation, letter numbers, a supplementary letter, isolated surrogates,
separators and 400 seeded mixes); and every char and code point for the
identifier ranges. The facts it pins include:

- `\R` treats CRLF as one break and U+0085, U+2028 and U+2029 as breaks;
  `\s` excludes U+00A0, U+0085 and U+3000, so a no-break space never splits
  a tag value or collapses a table cell.
- `\s*\R\s*` turns a space run holding a break into one space, absorbs a
  U+0085, U+2028 or U+2029 that directly follows the run with the run after
  it, and keeps a run without a break.
- `(?i)` folds ASCII only; `</code>$` also matches before a final U+0085.
- Entities: `&#X41;` (uppercase X) is literal text; values above the int
  range or U+10FFFF raise the existing diagnostic; surrogate values become a
  lone unit; leading zeros are accepted.
- 424 tag suffixes give `unsupported IronDocs tag @<name>` with Java's name
  boundary; a name stops at a supplementary letter's high surrogate (so
  `@param` followed by one still names `param`) and at a U+2028 line break.

## Provenance

The scans and lookup are original code under the default license. The
identifier ranges are Unicode 15.0 character data that JDK 21 reports through
`Character`; no OpenJDK source was consulted. They are treated as the project
treats its other observed Character data and carry the Unicode notice
(`LICENSES/Unicode-15.0.txt`), as SOURCE_PROVENANCE and THIRD_PARTY_NOTICES
record. A maintainer who prefers to classify generated property data with the
derived runtime tables can reclassify this one file without changing code.

## What S6 and M6.1 still do

S6 ports the documentation tools and IronJarMain onto these helpers and
compares their pages, diagnostics and exit codes with the Java tools on the
IronDocs fixtures. M6.1 adds Java 21's identifier-start predicate, the
reserved and contextual keyword rules and qualified-name validation for
Bridge exports, sharing this table.
