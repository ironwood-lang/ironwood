# M6.1: Java 21 name validation for Bridge exports (D291)

Scope: B7's qualified-name validation for the exact-package export checks of
BridgePackageInputs.discover and BridgeExportSurface.select, sharing the
Java 21 identifier table that M5.4 delivered for the documentation tag scan.
It prepares S7's ports of those callers; it is not those ports.

| Port source | Replaces |
| --- | --- |
| [JavaIdentifiers.iron](../../../compiler/src/main/ironwood/ironwood/compiler/port/JavaIdentifiers.iron) | `Character.isJavaIdentifierStart(int)` (added) and `isJavaIdentifierPart` (M5.4), generated by [JavaIdentifierTable.java](../m5/doc-evidence/JavaIdentifierTable.java) |
| [JavaNames.iron](../../../compiler/src/main/ironwood/ironwood/compiler/port/JavaNames.iron) | `SourceVersion.isName(name, RELEASE_21)`, `isIdentifier` and `isKeyword(name, RELEASE_21)` |
| [BridgeExports.iron](../../../compiler/src/main/ironwood/ironwood/compiler/port/BridgeExports.iron) | The two callers' export loops with their `TreeSet<String>` packages and global diagnostics |

`isName` splits at every dot with Java's limit -1, so an empty, leading,
trailing or repeated-dot component fails. A component's first code point must
be an identifier start and the rest identifier parts; a high surrogate
followed by a low surrogate is one code point, any other surrogate is tested
alone and is neither. A component that is a JLS 21 reserved keyword (`_`
included) or `true`, `false` or `null` fails; contextual keywords (`record`,
`var`, `yield`, `sealed`, `permits`, `when`, `module`, `open`, `opens`,
`exports`, `requires`, `transitive`, `uses`, `provides`, `to`, `with`) pass,
and `non-sealed` fails only as a non-identifier.

## Semantics checked against JDK 21

[JavaNamesReference.java](names-evidence/JavaNamesReference.java) calls
`SourceVersion.isName`, `isIdentifier` and `isKeyword` with `RELEASE_21` and
runs the two callers' exact loops. The corpus has 4,245 names: 95 chosen
forms, the 50 reserved keywords each alone, qualified (`a.int`) and suffixed
(`ints`), and 4,000 seeded mixes of ASCII letters and digits, `_`, `$`,
dots, space and `-`, `é`, `中`, U+0661 (an Arabic-Indic digit: a part, not a
start), U+00AD and U+200B (identifier-ignorable), U+0301 (a combining mark),
`€`, U+203F (connecting punctuation), U+216B (a letter number), the halves
of U+1D400 and U+1D7CE, an isolated high surrogate, NUL and DEL. Seventy
export groups cover empty requests, duplicates, invalid and reserved names,
and 60 seeded mixes. The facts it pins include:

- `_` alone and as any component is a keyword (`a._.b` fails); `$`, `$a` and
  `a$` are names.
- U+0661, U+00AD, U+200B and U+0301 are parts but not starts; NUL after a
  letter is a part (identifier-ignorable), before one it fails.
- `a` followed by an unpaired high or low surrogate fails; the paired
  mathematical bold capital A (U+1D400) is a start, and the paired
  mathematical bold digit zero (U+1D7CE) only a part.
- BridgeExportSurface reports `ironwood.bridge` as reserved and
  BridgePackageInputs accepts it; only package inputs report an empty
  request.

## Provenance

The lookup and validation code is original under the default license. The
start ranges are Unicode 15.0 character data that JDK 21 reports through
`Character`, generated without OpenJDK source like M5.4's part ranges, and
carry the Unicode notice (`LICENSES/Unicode-15.0.txt`); SOURCE_PROVENANCE and
THIRD_PARTY_NOTICES now name both predicates. The keyword list follows JLS 21
sections 3.9 and 3.10.

## What S7 still does

S7 ports BridgePackageInputs and BridgeExportSurface onto `BridgeExports`,
wrapping each message in a global diagnostic, keeping the package inputs'
early return on any diagnostic and the export surface's later checks, and
compares their diagnostics with the Java seed on the Bridge export fixtures.
