# M6.1: remaining compiler-local contracts

Scope: B7's remaining compiler-local contracts for S7's Bridge consumers:
Java 21 qualified export-name validation sharing the S6 identifier table,
the remaining properties and JAR manifest helpers, exact Bridge and TLS
inventory serialization, and traversal coverage for each Bridge consumer
brought into the port. It classifies every pattern of the M0 inventory's
`M6.1 before M6.2` gate and gives the M0 contract rows that name M6 their
treatment. It prepares S7; it ports none of its consumers.

Every transcript equals the Java baseline's own methods or JDK 21's APIs from
class and archive links, every result is freed, the ownership pairs hold in
every unfreed mode, and every allocation failure unwinds.

## Inventory reconciliation

[CLASSIFICATION_M6.1.md](CLASSIFICATION_M6.1.md), generated by
[classify.py](../m3/classify.py) with phase-scoped M6.1 rules, assigns each
of the 387 patterns exactly one class: the 385 patterns of the
`M6.1 before M6.2` gate and the two `HexFormat` patterns whose gate reuses
the M3.2 digest-text helper at M6.1 (8,242 calls).

| Class | Calls | Patterns | Meaning |
| --- | --- | --- | --- |
| A | 5,109 | 128 | existing Ironwood member, declaration verified in source |
| B | 2,183 | 127 | recorded port convention |
| D | 950 | 132 | delivered helper (D248-D277, D291-D295) |

140 patterns take one of the 88 M6.1 rules, every one of which is used; the
other 247 keep the general M3 rules, whose collection, Optional, stream,
string and path treatments hold for the Bridge sites. The M6.1 rules replace
general rules written for earlier consumers where the Bridge differs, for
example `String.matches` (BridgePatterns rather than HeaderScan),
`Properties` (BridgeProperties' escapes rather than PropertiesText's subset),
`Files.move` (`moveAtomicReplacing` and `moveAtomicNoReplace`) and
`StringBuilder(String)` (the M5 limit). The classification regenerated the
eight earlier tables byte for byte. After M6.2, rows cite D294's BridgeJar,
JarStreams and destination check and D295's JdkSelection, moving
`Files.newOutputStream`, `Runtime.version`, `Runtime.Version.feature`, the
tool argument array and `Collection.toArray` from B to D; the counts above
are the regenerated table's.

Two B rules name boundaries rather than helpers: the Java compiler's class
or jar inventory, code source and VERSION text are the producer identity S7
redesigns, and `Float.floatToRawIntBits` becomes a constant's raw-bit payload
rather than a public method (D293). The running JVM's home, version and
vendor, first a pending boundary, are JdkSelection's since D295.

## Traversal coverage

The Bridge consumers brought into the port read their files through B3's
replacements: `SourceFiles` for the runtime `.c`/`.h` inventory,
`FileCollector` at depth one for export package and distribution stage
listings, `FileCollector` for the assembler's class walk, and `TreeDeletion`
for every reverse-sorted staging cleanup ([TEXT.md](TEXT.md#traversal-coverage-for-the-bridge-consumers)).
The walk test compares their selections, spellings, digests and identity with
Java's `Files.walk` and `Files.list`. The Bridge's IR scanners (C10-C12) keep
D265's walk contract for S7.
